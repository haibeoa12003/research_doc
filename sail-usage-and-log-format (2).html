0. General: supported extensions and golden-model configuration

A golden model is a reference that implements the same ISA and the same implementation-defined choices as your CPU, so that a trace diff shows only real differences. With sail-riscv you get this from the configuration file: the extension list, the WARL behaviour of CSRs, the optional traps, the memory map and the platform devices. This section lists what the model supports (0.1), what the configuration can set (0.2 to 0.3), what it cannot set (0.4), a recipe (0.5) and two tested example configurations (0.6, 0.7).

0.2 How the configuration is applied

  • The configuration is JSON with // comments, in four objects: base, memory, platform, extensions. Every key is required by the schema (--print-config-schema).
  • --config <file> replaces the whole configuration. --config-override <patch> merges a patch over the default (or over --config), can be given several times, and cannot add keys (4.3).
  • Every run validates the configuration first. --validate-config validates and exits; the reasons for a rejection go to stdout (4.4).
  • Recommended: keep your core as a patch over the built-in default (--config-override, plus --rv32 for a 32-bit core). A patch names only the keys you change, so a new key in a later sail-riscv release takes its default value; a full file must list every key and stops validating when the schema gains one (inferred from the schema rules). For example, the CVA6 sail.json shipped with ACT4 fails --validate-config against 0.16 with about 28 errors (research report, section 1).

Nonzero at step 0 with the default RV64 config: mstatus.SXL=UXL=2, hstatus.VSXL=2, vsstatus.UXL=2, mip.MTIP=1 (mtimecmp starts at 0), tdata1=0xF000000000000000 (triggers disabled), tinfo=0x1008078. mstatus.FS=VS=0, so fcsr and the vector CSRs trap until software sets them. No key sets other reset values; read the CSRs at the start of a test and compare them with the RTL. model/sys/sys_control.sail:538-610, model/postlude/model.sail:10-21 07/A7_reset_values
a0 and a1 at reset Before step 0 the harness sets a0 = mhartid and a1 = memory.dtb_address (0x1000), and no trace line shows it. If your RTL resets them to 0, a test that reads a1 before writing it will differ. model/postlude/model.sail:36-38 06_golden_config (boot_regs.log), 07/D6_dtb
Number of harts One. --harts is rejected, and the device tree has one cpu@0. c_emulator/sail_riscv_sim.cpp:51, model/sys/platform.sail:58-60 07/A8_harts
Interrupt controller No PLIC and no AIA. The AIA CSRs (miselect, mireg, mtopi and the others) are illegal instructions. 0xC000000, the usual PLIC base, is the simple interrupt generator, which reads its version 0x00010001 there. External interrupts come only from that generator, or from software writing mip.SEIP. 4.1 07/D7_no_plic_aia
Timing No pipeline, caches or cycle counts: every instruction is one step. minstret counts retired instructions (a step that traps, such as ecall or an illegal instruction, is not counted). mcycle, time and mtime all add 1 every platform.instructions_per_tick (2) steps and 1 per WFI/WRS wait tick, so by default mcycle is about half the step count. The TLB is a fixed 64-slot model structure. 9.4, 9.5, model/sys/vmem_tlb.sail:77-81 03_interrupts/c1_mtimer, 07/D9_timing
Byte order Little-endian only. Writes to mstatus.MBE, SBE, UBE (and mstatush on RV32) read back 0. model/core/sys_regs.sail:255-256 07/A9_endian
Custom instructions and CSRs The custom-0 to custom-3 opcodes and custom CSR numbers are illegal instructions, and there is no plugin option. Edit the Sail source (hooks such as ext_decode and ext_reset) and rebuild. research report 3.5, model/postlude/decode_ext.sail:13-15 07/A10_custom
WFI or WRS wake-up with nothing pending No option for a wake-up at a random point. A WFI or WRS that is not a NOP always ends its wait after platform.max_time_to_wait (10) time ticks, even with nothing pending. WFI then retires in M mode, and in S/U mode unless mstatus.TW=1 (a U-mode WFI also traps when S exists). WRS.NTO retires unless TW=1 outside M; WRS.STO always retires. 0.5 Recipe: a configuration for your core

  1. Write down your core's ISA string and pick the base: the RV64 default, or --rv32.
  2. Generate a patch that turns off every extension your core lacks: cases/06_golden_config/mkpatch.py writes it from a keep-list (commands after this list).
  3. Run sail_riscv_sim --config-override my_core.json --validate-config and fix each reason it prints (table below), until it says is valid.
  4. Check --print-isa-string, then run a test that reads misa and the ID CSRs (cases/06_golden_config/id_csrs.S) and compare the values with the RTL.
  5. Go through the tables in 0.3 with your core's specification: PMP count and grain, mtvec modes, medeleg, xtval_nonzero, misaligned policy, memory map, CLINT address and the ID CSRs. Put the answers in the same patch, or in a second patch passed after the first.
  6. Run the riscv-tests for your ISA (cases/06_golden_config/run.sh shows how). Tests for extensions you turned off fail on purpose; the rest must pass. Keep the patch in version control and run --validate-config again after every sail-riscv upgrade.

1.2 Write and build a test

A bare-metal test needs three things: code linked at 0x80000000 (start of RAM), a tohost symbol (the HTIF mailbox that ends the run), and a write of (code << 1) | 1 to tohost. The shared files in cases/common/ provide all three:

File Content
cases/common/link.ld .text.init at 0x80000000, .tohost on the next 4 KiB boundary, then .text, .data, .bss
cases/common/test_macros.h HTIF_SECTION (defines tohost/fromhost), EXIT_WITH(code), PASS (= EXIT_WITH(0)), FAIL (= EXIT_WITH(1))
cases/common/build.sh build.sh <src.S> <out.elf> [rv64\|rv32] [march]

Default -march is rv64imafdc_zicsr_zifencei (lp64d) or rv32imafdc_zicsr_zifencei (ilp32d). Pass a fourth argument to change it, for example rv64gcv_zicsr_zifencei for vector code.

4.3 --config-override <file>

A patch is a JSON object (comments allowed) merged into the base config (c_emulator/riscv_sim.cpp:64-130):

  • Objects merge key by key. Every key must already exist in the base: overrides cannot add keys.
  • Arrays and scalars are replaced whole (the JSON type must match). To change one memory region you must give the whole memory.regions array.
  • When the base object and the override object each have exactly one key and the keys differ, the override replaces the object. This is how a union variant is changed, for example {"None": null} to {"Some": "AlignmentException"}.
  • The option is repeatable; later files win.
  • After merging, the result is schema-checked and then semantically validated.

Format (model/postlude/step.sail:167 for 16-bit, :205 for 32-bit instructions):

Field Example Meaning
[N] [37] Step number, decimal from 0 (riscv_sim.cpp:512,568). All exception steps have the same shape: instruction line, (PMP/PMA explanation if any), trapping from X to Y to handle <name>, handling exc#<name> at priv Y | tval=... | tval2=... | tinst=..., then the trap CSR group (5.9), then the handler's first fetch. A fetch fault and an execute-address trigger have no instruction line.

6.7 Interrupts

Common shape of an interrupt step (model/postlude/step.sail:268-401):

  1. CSR mip (0x344) <- ...: printed at the start of the step that sees the pending bit change (needs --trace-csr).
  2. Handling interrupt: 0b<cause>: on stdout (needs --trace-instr).
  3. handling int#<name> at priv <P> | tval=0 | tval2=0 | tinst=0: in the trace log. There is never a trapping from line for an interrupt.
  4. The trap CSR group, with the interrupt bit set in xcause.
  5. No instruction line: the interrupt uses a step number, so the trace jumps (for example [25] to [27]).
  6. mepc = the address of the instruction that has not run yet.

Entry does not clear mip: interrupts are level-sensitive and stay pending until the source is cleared.

7. Ordering rules within one step

One iteration of the harness loop (c_emulator/riscv_sim.cpp:519-608) and one try_step (model/postlude/step.sail:268-401) print in this order. Items that do not apply are skipped. Confirmed from the source and matched against the runs in sections 5 and 6.

  1. RVFI pre-step lines (stderr), in --rvfi-dii mode only.
  2. CSR mip (0x344) <- ... if update_mip() found a change (timer, CLINT, SIG). This is the first line of the step, before any fetch.
  3. If the hart is waiting (WFI/WRS): remaining in ..., or interrupt exit from ... / forced exit from ... / timed-out exit from ....
  4. A pending "after" trigger (icount, itrigger, etrigger): Fired ..., then Handling trigger at index #N, then the trap lines (item 9). No instruction line.
  5. A pending interrupt: Handling interrupt: 0b...... (stdout), then the trap lines (item 9). No instruction line.
  6. An execute-address trigger: Matched ... execute address trigger ..., Handling trigger ..., Fired ..., then the trap. No fetch and no instruction line.
  7. Fetch: PTW lines for the fetch translation, with the PTE mem[R,...] reads and any A/D mem[W,...] between PTW: Success and TLB add, then the TLB add table, then (PMP/PMA ... failed if the fetch faults) or the mem[X,...] fetch line(s). A fetch fault goes straight to the trap lines: no instruction line.
  8. The instruction line [N] [P]: ... (after decode, before execute), then in program order:
    1. data-side PTW lines and TLB add (a TLB hit prints nothing except a possible A/D mem[W] write-back)
    2. PMP check failed ... / PMA ... check failed ...
    3. Matched ... trigger ... for load/store triggers, then Handling trigger, Fired
    4. MMIO device line (clint..., htif[...], htif-... cmd:), then the mem[R|W|RW|RX|C,...] line of the same access. Exception: the SIG prints its CSR mip line before its mem[W] line.
    5. for a CSR read: CSR ... ->, then the rd write
    6. for a CSR write: the rd write (xN <- old) first, then CSR ... <-
    7. register write lines (xN, fN, vN), with CSR mstatus after each fN write and before each vN write
    8. FP: (CSR mstatus if fflags changes), CSR fflags, CSR fcsr, the fN write, CSR mstatus
    9. vector loads/stores: per element CSR mstatus, CSR vstart, mem[...], (CSR mstatus, vN <- for loads)
  9. Trap: trapping from X to Y to handle <exc> (exceptions only) -> setting ...[MDT/SDT] for Double Trap -> handling exc#/int#... -> Matched icount ... (if an icount trigger counts traps) -> CSR tcontrol (M traps, Sdtrig) -> CSR mstatus (+ mstatush on RV32) -> cause, tval, epc -> H-only CSRs (mtval2, mtinst or hstatus, htval, htinst); a trap into VS logs vscause, vstval, vsepc, vsstatus after mstatus instead -> Exception ... matched etrigger / Interrupt ... matched itrigger.
  10. xRET: clearing ...[MDT/SDT] for Double Trap -> CSR tcontrol (mret) -> CSR mstatus -> CSR vsstatus (sret from VS; mret or sret into VU with henvcfg.DTE=1) or CSR hstatus (other sret, H enabled) -> ret-ing from X to Y.
  11. entering WAIT-... state at PC ... when the instruction starts a wait.
  12. With --trace-instr: flush of the trace log and stdout.
  13. The --trace-step empty line (not for waiting steps).
  14. SUCCESS or FAILURE: N after the step that completed the HTIF exit command; the run stops.
  15. The trap-loop check (FAILURE: possible trap loop ...) after the clock tick.

Two consequences for parsers:

  • Lines that come before an instruction line can belong to it (its fetch, fetch PTW, the CSR mip update) or to a step with no instruction line (interrupt, fetch fault, trigger). Use --trace-step to get an empty line at the end of each step and group by blocks.
  • The trap CSR lines are printed after the whole trap state update, so they show final values in a fixed order. The model's own update order is different (mcause, mstatus, mtval, mtval2, mtinst, mepc, privilege, tcontrol: model/sys/sys_control.sail:297-316); do not use the log order to reason about update order.

The script below uses these patterns. It was run on 15 captured logs (RV64 and RV32, traps, interrupts, WFI, VM with TLB tables, hypervisor, FP, vector, triggers, PMA, double trap, HTIF); the only unclassified lines were the two glued HTIF lines of cases/01_basics/case5_htif_console/G.stdout (section 9).

python
#!/usr/bin/env python3
"""Classify every line of a sail_riscv_sim 0.16 trace and group lines per step."""
import re
import sys

PRIV = r"(?:M|HS|S|U|VS|VU)"
PATTERNS = [
    ("instr",   re.compile(r"^\[(\d+)\] \[(" + PRIV + r")\]: 0x([0-9A-F]+) \(0x([0-9A-F]{4}|[0-9A-F]{8})\) (.+?)(?: {4,}(\S+)\+(\d+))?$")),
    ("gpr",     re.compile(r"^(x\d+|zero|ra|sp|gp|tp|t[0-6]|s\d+|a[0-7]) <- 0x([0-9A-F]+)$")),
    ("fpr",     re.compile(r"^f(\d+) <- 0x([0-9A-F]+)$")),
    ("vreg",    re.compile(r"^v(\d+) <- 0x([0-9A-F]+)$")),
    ("csr",     re.compile(r"^CSR (\S+) \(0x([0-9A-F]{3})\) (<-|->) 0x([0-9A-F]+)$")),
    ("mem",     re.compile(r"^mem\[([A-Z.]+),0x([0-9A-F]+)\] (->|<-) 0x([0-9A-F]+)$")),
    ("trap",    re.compile(r"^trapping from (" + PRIV + r") to (" + PRIV + r") to handle (\S+)$")),
    ("handling", re.compile(r"^handling (exc|int)#(.+?) at priv (" + PRIV + r") \| tval=0x([0-9A-F]+) \| tval2=0x([0-9A-F]+) \| tinst=0x([0-9A-F]+)$")),
    ("xret",    re.compile(r"^ret-ing from (" + PRIV + r") to (" + PRIV + r")$")),
    ("irq",     re.compile(r"^Handling interrupt: 0b([01]+)$")),
    ("wait",    re.compile(r"^(entering|remaining in|interrupt exit from|forced exit from|timed-out exit from|reservation invalid exit from) (WAIT-\S+) state at PC 0x([0-9A-F]+)$")),
    ("ptw",     re.compile(r"^PTW: (Start|Step|Success|Failed), stage=(\w+), level=(\d+), (.*)$")),
    ("tlb",     re.compile(r"^TLB (add|flush) \[ len=(\d+) \]$")),
    ("tlbrow",  re.compile(r"^[═-╬]")),
    ("clint",   re.compile(r"^clint(?:<[48]>|-hi<4>)?\[(0x[0-9A-F]+|0b[01]+)\] (->|<-) (.*)$")),
    ("htif",    re.compile(r"^htif(?:\[0x[0-9A-F]+\] (?:->|<-) 0x[0-9A-F]+|-syscall-proxy cmd: 0x[0-9A-F]+|-term cmd: 0x[0-9A-F]+)$")),
    ("pmp",     re.compile(r"^PMP check failed ")),
    ("pma",     re.compile(r"^(?:MAG )?PMA (?:access )?check failed for a (\d+)-byte wide (\S+) access to address 0x([0-9A-F]+) with PMA \{(.*)\}$")),
    ("trigger", re.compile(r"^(Matched |Fired |Handling trigger |Cannot create |Creating disabled |Interrupt .* matched itrigger|Exception .* matched etrigger|(disabled|icount|itrigger|etrigger|mcontrol6 \(chain=0b[01]\)) trigger #\d+)")),
    ("dbltrp",  re.compile(r"^(setting|clearing) (m|vs)status\[(MDT|SDT)\] for Double Trap$")),
    ("blank",   re.compile(r"^$")),
    ("banner",  re.compile(r"^(HTIF located at|Entry point:|begin_signature:|end_signature:|Loading additional ELF file)")),
    ("result",  re.compile(r"^(SUCCESS|FAILURE: .*)$")),
]


def classify(line):
    for name, rx in PATTERNS:
        m = rx.match(line)
        if m:
            return name, m
    return "other", None


def main(path):
    counts = {}
    others = []
    steps = []          # list of (step_no, priv, pc, enc, [lines])
    pending = []        # lines printed before the next instruction line (fetch, fetch PTW, mip update...)
    with open(path, encoding="utf-8", errors="replace") as f:
        for raw in f:
            line = raw.rstrip("\n")
            kind, m = classify(line)
            counts[kind] = counts.get(kind, 0) + 1
            if kind == "other":
                others.append(line)
            if kind == "instr":
                steps.append([int(m.group(1)), m.group(2), m.group(3), m.group(4), pending + [line]])
                pending = []
            elif steps and kind in ("gpr", "fpr", "vreg", "csr", "mem", "trap", "handling", "xret", "pmp", "pma", "clint", "htif", "trigger", "dbltrp"):
                # belongs to the last instruction, unless it is a fetch of the next one
                if kind == "mem" and m.group(1) == "X":
                    pending.append(line)
                else:
                    steps[-1][4].append(line)
            else:
                pending.append(line)
    print(path)
    print("  line kinds:", dict(sorted(counts.items())))
    gaps = [b[0] for a, b in zip(steps, steps[1:]) if b[0] != a[0] + 1 and b[0] > a[0]]
    print("  instruction lines:", len(steps), " step-number gaps (trap/interrupt/fetch-fault steps) before steps:", gaps[:10])
    for o in others[:5]:
        print("  unclassified:", o[:120])


if __name__ == "__main__":
    for p in sys.argv[1:]:
        main(p)

8.7 Number formats

  • Trace values: upper-case hex with 0x, zero-padded to the field width.
  • Symbol offsets: decimal (alu+12 is 0xC bytes after alu).
  • Banner and trap-loop addresses: lower-case hex, not padded (HTIF located at 0x80001000, MEPC=0x8000000c).
  • PTW vpn and final_ppn: lower-case hex, not padded. pte, pte_addr: upper-case, not padded.
  • Any Sail bits_str of a width that is not a multiple of 4 prints in binary: Handling interrupt: 0b000111, RV32 CLINT offsets.
  • Signature files: lower-case hex, no 0x.

8.8 The symbol column

  • It is the nearest ELF symbol at or below the PC, from the first ELF. All NOTYPE, FUNC, OBJECT and COMMON symbols are used, including local labels and assembler mapping symbols: after .option rvc/norvc or a .word in .text you get $xrv64i2p1_m2p0_..._zcd1p0+10 or $d+0. objdump -t hides these; readelf -s shows them. A real label at the same address wins (alphabetically last name wins, and $ sorts first).
  • Symbol names are kept in a map keyed by name, so a repeated name keeps only its last address.
  • PCs are symbolized as virtual addresses. For code running at VAs outside the link map the result is meaningless (freelist_head+18446744071559934232, _end+1073705268) or missing.
  • No ELF (RVFI mode) or no symbol below the PC: the column is omitted entirely.

8.9 Box-drawing characters in TLB tables

The TLB tables use UTF-8 box-drawing characters U+2550 to U+256C (double lines and corners), 3 bytes each (E2 95 xx). Byte-oriented tools count 3 columns per character. Useful filters:

shell
grep -v '║  - ║.*║$' trace.log                   # drop empty rows (cases/04_vm/common/compact_tlb.sh)
LC_ALL=C grep -a $'\xe2\x95\x91' trace.log        # match table rows by bytes
sed 's/[║╔╗╚╝╠╣╦╩╬═]/|/g' trace.log               # convert to ASCII (UTF-8 locale)

The rows tagged <- added and <- flushed are the only ones that describe the event.

8.10 What --trace leaves out

  • PTW and TLB lines: add --trace-ptw --trace-tlb.
  • gdbserver lines: add --trace-gdbserver (with --gdb-server-port).
  • ABI names: add --use-abi-names.
  • Register reads (no flag prints them), CSR reads of read-modify-write instructions, counter increments, faulting memory accesses (no mem[] line), TLB hits, PC redirects.
  • Lines that never go to the trace file even with --trace-output: banner, SUCCESS/FAILURE, Handling interrupt:, HTIF unknown-command messages, console characters.

8.11 Streams and buffering

  • stdout is block-buffered when redirected. Console bytes (write()), stderr lines and stdout lines can appear in a different order than they happened. --trace-instr flushes after every step, which keeps the order close.
  • A run killed by timeout loses buffered stdout. Use stdbuf -oL or --trace-instr, and --trace-output for the trace.
  • --trace-output /dev/stderr while stderr goes to a file truncates that file (fopen with "w+").

9. Known gaps and surprises found while testing

All items were observed in the runs unless marked "source only" or "inferred".

9.1 Pass/fail and run control

  1. --inst-limit and --stop-at-pc end the run with exit 0 and no message. A script that checks only the exit status counts them as passes. Check for SUCCESS.
  2. Every HTIF failure code gives exit status 1; the code is only in the FAILURE: N text.
  3. On FAILURE (HTIF or trap loop) the end-of-run step is skipped: no signature file, no memory dump, no --show-times summary.
  4. RV32 tests built with the shared cases/common/test_macros.h never end: a single sw to tohost does not complete an HTIF command. Write tohost+4 too (1.2). Four areas hit this or worked around it with a local macro (01_basics/case3, 02_traps_csr/c01 RV32, 03_interrupts/c1 RV32, 04_vm/05 Sv32); case3_rv32_vs_rv64/rv32_shared_macro_hang.log shows the hang.
  5. bne ..., 1f just before PASS jumps into the 1: j 1b inside the macro, so a failing check spins until timeout instead of reporting FAILURE (cases/04_vm tests).
  6. The trap-loop detector only catches loops with no xRET. A handler that returns with mret each time loops until --inst-limit (exit 0).
  7. --stop-at-pc is not triggered by the reset PC (only by a PC reached at the end of a step), so --stop-at-pc <entry> runs to completion unless the code jumps back to the entry; a symbol name is rejected.
  8. Overlapping ELF segments are an error, although --help says later ELFs may overwrite earlier ones. tohost and the signature symbols are only looked up in the first ELF.
  9. A failed --dump-memory file creation still exits 0. With the default config the dump is 2 GiB.

9.2 Trace content

  1. [N] counts steps, not retired instructions. Steps that take an interrupt, fault at fetch, or take a fetch-time or pending trigger print no instruction line, so the numbers have gaps ([25] then [27]).
  2. Register traces print writes only, although --help says "reads and writes". Writes to x0 are not logged; writes of unchanged values are.
  3. A CSR read line (->) appears only for pure-read CSR instructions. A read-modify-write logs xN <- first, then CSR <-.
  4. CSR ... <- shows the legalized value, not the operand (locked pmpcfg, WARL mstatus, sie masked by mideleg, menvcfg.ADUE without Svadu).
  5. CSR mip (0x344) <- ...80 appears before step 0: mtimecmp resets to 0, so MTIP is pending from reset. With Sstc the same happens to STIP as soon as menvcfg.STCE is set.
  6. CSR tcontrol lines on every M trap and mret, although tcontrol is not an accessible CSR in the default config.
  7. FP writes always add a CSR mstatus line; FP ops always print fflags/fcsr, with sticky values; fN lines stay numeric with --use-abi-names.
  8. Vector loads print one mem[] line per element, a vstart line per element, and the whole register after each element, including tail and masked elements. vsetvli prints vstart twice.
  9. With FS=Off an FP instruction disassembles as illegal 0x....
  10. The disassembler uses no aliases, signed hex immediates and PC-relative branch offsets; compare encodings, not text.
  11. A misaligned access is one mem[] line even when split internally; the split is invisible.
  12. A failed SC prints no memory line. cbo.clean/flush/inval print no memory line. A faulting access prints no mem[] line.
  13. PTE reads and A/D writes use the plain R/W letters.
  14. The model fetches 4 bytes at a 4-byte-aligned PC even for a compressed instruction; with Ziccif off it fetches 16 bits at a time.

9.3 Traps and privilege

  1. S-mode prints as HS in the default config (H enabled). Turning H off with one override key fails validation (about 11 dependent keys); clearing misa.H at run time gives S.
  2. Trap groups include mtval2/mtinst (M) and hstatus/htval/htinst (S) whenever H is enabled: configured and misa.H=1 (currentlyEnabled(Ext_H), model/sys/sys_control.sail:201,210). Clearing misa.H at run time removes them.
  3. For a double trap in S, trapping from says HS to HS while handling says exc#double-trap at priv M. An M-mode double trap stops the run with Assertion failed: unexpected trap taken in machine mode (stderr, exit 1).
  4. ret-ing from needs --trace-exception; --trace-interrupt alone prints only handling lines.
  5. .word 0 executes as c.illegal (2 bytes).
  6. Without a PMP entry, the first S or U access faults (PMP check failed with no matching entry.): the default config has 16 PMP entries.
  7. An access outside every PMA region faults with no PMA message; with neither a PMP nor a PMA line, the address is unmapped.

9.4 Interrupts and time

  1. mtime is the step count divided by instructions_per_tick, plus one tick per WFI wait iteration. Interrupt steps count too. It has no relation to wall-clock time; clock_frequency only feeds the device tree (timebase-frequency = clock_frequency / instructions_per_tick).
  2. Handling interrupt: 0b... goes to stdout even with --trace-output.
  3. After mret, the next pending interrupt is taken immediately, with no instruction in between.
  4. WFI retires before the interrupt is taken, so mepc is the instruction after the WFI. WFI wakes on mip & mie even with mstatus.MIE=0, and spends one wait iteration even if an interrupt is already pending.
  5. The simple interrupt generator never appears in --trace-clint or --trace-platform; with it disabled its address is plain memory (no fault).
  6. The CLINT trace prints the whole 64-bit mtime for 4-byte reads, even of the high word; on RV32 the CLINT offset is printed in binary.
  7. With H on, writing 0x22 to mideleg reads back 0x1466.

9.5 Virtual memory

  1. --trace does not enable PTW or TLB lines.
  2. Page faults with no PTW: Failed line: TLB-hit faults, non-canonical VAs, and A/D updates needed with hardware update off (PTW: Success then the fault).
  3. The TLB table is printed after a flush, so flushed rows already show ----; a flush that removes nothing prints nothing; a TLB hit prints nothing.
  4. The model TLB is a 64-slot direct-mapped structure indexed by VPN[5:0] XOR stage; superpages fill several identical slots. Walk counts and TLB contents will not match RTL.
  5. The TLB VPN column is sign-extended (Sv32 VA 0x80000000 shows 0x0000007FFFFFF80000); the PTW vpn is zero-extended.
  6. VS-stage: PTW: Step pte_addr is supervisor-physical, the TLB PTE_ADDR is guest-physical. G-stage walks print privilege=U.
  7. menvcfg.ADUE resets to 0, so the default config takes page faults for A/D unless PTEs are preset.
  8. The -v riscv-tests produce about 15 MB of log per 2,800 steps with --trace-tlb.

9.6 Streams, HTIF and options

  1. SUCCESS, FAILURE and the banner never go to the --trace-output file.
  2. Console characters are written unbuffered and can appear before earlier stdout lines (Hi Sail! before HTIF located, H[11] ...). Use --terminal-log.
  3. Unknown term cmd: and htif-???? cmd: print without a flag and without a newline.
  4. Only the console device clears tohost after a command; after an unknown-device or non-exit device-0 command a program polling tohost for 0 would spin (inferred).
  5. --trace-rvfi does nothing without --rvfi-dii. RVFI packets carry rs1/rs2 fields that are always 0 (inferred from source).
  6. The gdb server listens on all IPv4 interfaces (0.0.0.0), the RVFI socket on 127.0.0.1 only.
  7. Config validation reasons go to stdout, the summary to stderr. Arrays in --config-override replace the whole array.
  8. --show-times counts signature and memory-dump writing as execution time.

9.7 Not verified

Source only, never triggered in these runs: most Sdtrig rejection messages (only Cannot create unsupported trigger type 0x3. was seen, in 07_config_coverage/D_platform/D5_triggers), PMP ... partial match in the cases runs (it was seen in work/catalog_runs/pmp.out), shadow-stack .ss access letters, virtual-instruction exceptions, Sv57, the counter-overflow interrupt, VS-level interrupts, and RVFI/gdb error paths. Triggered later in 07_config_coverage: the reservation invalid exit WRS message (D4_wfi_wrs), a load guest page fault (B8_htval), and WFI in S mode with mstatus.TW=1 (D8_spurious_wfi).
